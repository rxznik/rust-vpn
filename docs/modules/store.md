# rvpn-store

SQLite-хранилище. Границы — в [docs/architecture.md](../architecture.md).

## Ответственность

Крейт `crates/store` открывает один файл базы и хранит подписки, серверы, профили маршрута, группы, настройки ядра, непрозрачный JSON окна и ключи AES. Протокол сервера остаётся в теле записи. Процесс Xray читает applied-профиль, а не черновик.

## Файлы

Весь крейт — `src/lib.rs`.

## Основные типы

`Store` и `StoreError` (SQLite, битый JSON, отсутствие записи). Список для окна — `ServerSummary`: имя, адрес, порт и задержка колонками, без разбора тела протокола.

Таблицы: `subscriptions`, `servers`, `profiles`, `groups`, `core_settings`, `ui_settings`, `aes_keys`.

## Главный сценарий

`Client::open` создаёт `state.db`. Обновление подписки вызывает `replace_servers`: замена серверов и чистка ссылок в группах идут одной транзакцией. `connect` до запуска Xray вызывает `commit_routing`, и черновик копируется в applied.

## Как устроено

Журнал SQLite — WAL, `busy_timeout` — 5 секунд. На Unix каталог получает права `0700`, файл — `0600`. Подписка `local` создаётся при открытии и `delete_subscription` её не удаляет.

`commit_routing` копирует `draft_profile_id` в `applied_profile_id` и то же делает с флагом включения. Поколение кэша списка увеличивают `delete_subscription`, `upsert_server`, `replace_servers` и `set_delays`. Старая таблица `documents` переносится один раз и удаляется.

`ui_settings` хранит строку как есть: хранилище не знает полей темы. Ключи AES лежат в отдельной таблице сырыми байтами.

## Сильные стороны

Колонки списка читаются без разбора протокола. Замена серверов и членство в группах не расходятся по двум коммитам. Подписку `local` нельзя снести обновлением.

## Слабые стороны

Секреты в `state.db` записаны открытым текстом. Ключи не уходят в связку ОС. Права `0600` и `0700` есть только на Unix и защищают файл в пределах одного пользователя машины.
