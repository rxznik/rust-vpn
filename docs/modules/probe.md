# rvpn-probe

Проверки задержки и готовности локального SOCKS. Границы — в [docs/architecture.md](../architecture.md).

## Ответственность

Крейт `crates/probe` измеряет доступность узла и проверяет, что локальный входящий SOCKS уже принимает соединение. Конфиг Xray он не собирает.

## Файлы

Весь крейт — `src/lib.rs`.

## Основные типы

`ProbeError`: отказ соединения, таймаут, код ответа SOCKS и прочая ошибка. `socks_down` истинен только для отказа локального порта. Функции: `tcp_ping`, `icmp_ping`, `proxy_ping`, `tunnel_ready`, `parse_ping_ms`.

## Главный сценарий

Пинг списка в сессии выбирает тип из настроек: TCP, ICMP, GET через прокси или HEAD через прокси. После старта Xray сессия ждёт `tunnel_ready` на локальном SOCKS, прежде чем считать сессию поднятой.

## Как устроено

`tcp_ping` меряет `connect_timeout` до `host:port`. `icmp_ping` запускает одну команду `ping` и читает миллисекунды из `time=`, `zeit=` или `время=`, с суффиксами `ms` и `мс`. На Windows аргументы команды другие, чем на остальных ОС.

`proxy_ping` открывает SOCKS5 и шлёт GET или HEAD. Пустой логин — метод без пароля, непустой — имя и пароль. `tunnel_ready` для `https` или порта 443 пишет ClientHello и ждёт запись handshake или alert. Для обычного HTTP достаточно первого байта ответа. Отказ порта `127.0.0.1` помечается как `Refused`, чтобы интерфейс отличил мёртвый локальный SOCKS от ответа сервера.

## Сильные стороны

Локальный отказ не смешивается с таймаутом узла. Разбор ping понимает английский, немецкий и русский вывод. Проверка туннеля не требует отдельного бинарника.

## Слабые стороны

ICMP зависит от внешней команды `ping`. Проверка туннеля смотрит тип первой записи, а не завершённый обмен. Таймаут и адрес проверки задаёт вызывающий код, в крейте своих значений по умолчанию нет.
