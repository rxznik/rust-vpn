# rvpn-model

Доменные типы клиента. Сети и SQLite здесь нет. Границы крейта — в [docs/architecture.md](../architecture.md).

## Ответственность

Крейт `crates/model` задаёт сервер, подписку, профиль маршрута и настройки ядра. Сериализация — JSON. Новые поля имеют значение по умолчанию, поэтому старый документ открывается. Неизвестный тег `protocol` или `kind` не читается.

## Файлы

- `src/lib.rs` — `Server`, `ServerSummary`, формат трафика, `parse_flag`, `APP_USER_AGENT`
- `src/protocol.rs` — протокол узла, транспорт, TLS, Reality, fragment и noise
- `src/subscription.rs` — подписка, мета Happ, группа серверов
- `src/routing.rs` — профиль маршрута и команда из ссылки маршрута
- `src/settings.rs` — `CoreSettings` и перечисления портов, пинга, сортировки

## Основные типы

`Server` хранит имя, адрес, порт и `Protocol`: VLESS, VMess, Trojan, Shadowsocks, SOCKS, Hysteria2, WireGuard или сырой JSON. `Protocol::Json` компилятор ссылок не переписывает.

`Subscription` держит черновик маршрута (`draft_profile_id`, `draft_routing_enabled`) отдельно от применённого (`applied_profile_id`, `applied_routing_enabled`). Подписка `local` не удаляется хранилищем.

`CoreSettings` — порты, туннель, прокси, пинг и автозапуск. По умолчанию SOCKS `10808`, HTTP `10809`, API `10085`. Тема окна в эти поля не входит.

`PingType`: `tcp`, `icmp`, `proxy`, `proxy-head`. `AuthMode`: `auto`, `manual`, `from_json`, `disable`.

## Главный сценарий

Остальные крейты кладут в эти типы разобранную ссылку или тело подписки и потом читают их обратно из JSON. Черновик маршрута становится тем, что видит процесс, только после записи в applied-поля.

## Как устроено

`APP_USER_AGENT` равен `rustvpn/0.1`. Флаг Happ считает включёнными строки `true` и `1`, любое другое непустое значение — выключенным. Задержка короче 150 мс считается хорошей, короче 400 мс — средней. Лестница зума окна: 50, 75, 100, 125, 150, 175, 200. Размер шрифта: 12, 14, 16, 18, 20. Имя шрифта и группы отбрасывает пустую строку, управляющие символы и длину больше 80.

Поля меты, которые сессия копирует в работающие настройки, перечислены в комментарии крейта: прокси, TUN, sniffing, HTTP inbound, логин SOCKS и HTTP, список приложений, исключённые маршруты, no-limit, mux, тип пинга, URL проверки, fragment, noise и автозапуск. Остальные поля меты на процесс не влияют. Сортировка списка живёт в `CoreSettings`.

## Сильные стороны

Типы не ходят в сеть и не знают про файл базы. Старый JSON без новых полей открывается. Неизвестный протокол не превращается в пустой сервер.

## Слабые стороны

Секреты узла лежат в полях структуры открытым текстом: крейт их не шифрует. Собрать ссылку обратно из `Server` здесь нельзя. Модель не проверяет, что черновик уже применён к процессу.
