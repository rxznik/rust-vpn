# rvpn-platform

Хуки операционной системы: системный прокси, автозапуск, уведомление и идентификатор устройства. Границы — в [docs/architecture.md](../architecture.md).

## Ответственность

Крейт `crates/platform` меняет настройки ОС и отдаёт строки, которые сессия кладёт в заголовки обновления подписки. На ОС вне Linux, macOS и Windows системный прокси возвращает ошибку.

## Файлы

- `src/lib.rs` — трейт `Platform`, `HostPlatform`, снимок прокси, HWID
- `src/linux.rs` — GNOME через `gsettings`
- `src/macos.rs` — `networksetup`
- `src/windows.rs` — Internet Settings в HKCU
- `src/other.rs` — заглушка для остальных ОС

## Основные типы

`Platform`: поставить и вернуть системный прокси, автозапуск, уведомление, два идентификатора устройства, имя ОС, версию и модель. `ProxyMode` — `none`, `manual`, `auto`. Неизвестная строка снимка читается как `none`. `ProxyEndpoint` — хост и порт. `HostPlatform` кэширует имя ОС, версию и модель в `new`.

## Главный сценарий

При подключении с включённым системным прокси сессия указывает ОС на локальный SOCKS и HTTP. Перед записью текущие значения сохраняются в файл `proxy-snapshot`. Отключение и `shutdown` вызывают `restore_captured_proxy`. Автозапуск пишется вместе с сохранением `CoreSettings`.

## Как устроено

На Linux прокси — ключи `org.gnome.system.proxy`. Если `gsettings` нет, установка возвращает ошибку и файл снимка не трогает. Повторный снимок не затирает уже записанный файл. На macOS команды идут в `networksetup`, на Windows — в HKCU. Уведомление на Linux — `notify-send`, на macOS — `osascript`, на Windows вызов пустой.

HWID — 32 шестнадцатеричных символа в файле каталога данных. Зерно берётся из машины (`/etc/machine-id`, UUID платформы macOS или MachineGuid). Если зерна нет, пишутся случайные 16 байт. Файл на Unix получает права `0600`. Второй идентификатор считается от того же зерна с другим именем файла.

## Сильные стороны

Трейт позволяет тестам и будущим оболочкам подставить свой тип. Снимок прокси восстанавливается и не перезаписывается, пока сессия его держит. Идентификатор устройства стабилен между запусками.

## Слабые стороны

На Linux системный прокси есть только у GNOME, и у него нет поля пароля для локального SOCKS. KDE этот крейт не настраивает. Идентификатор лежит в файле данных, а не в связке ключей.
