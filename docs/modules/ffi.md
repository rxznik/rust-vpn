# rvpn-ffi

Фасад UniFFI для Android VpnService и iOS packet tunnel. Границы — в [docs/architecture.md](../architecture.md). В этот релиз мобильные оболочки не входят.

## Ответственность

Крейт `crates/ffi` выставляет `Client` наружу атрибутами UniFFI. Контракт задаёт `src/lib.rs`. Отдельный файл UDL в поставку биндингов не входит. Сами биндинги собираются при мобильной сборке и в репозиторий не кладутся.

## Файлы

- `src/lib.rs` — `VpnCore` и записи для списков
- `build.rs` — пустой шаг сборки

## Основные типы

`VpnCore` — один объект на каталог данных. `VpnError::Core` несёт текст ошибки строкой. Записи: `ServerView`, `DelayView`, `SubscriptionView`, `GroupView`, `SessionStatus`. У `DelayView` поле `delay_ms` равно `-1`, если проверка не ответила.

## Главный сценарий

Android вызывает `stage_session`, затем передаёт дескриптор TUN через `set_tun_fd`, затем `connect`. `shutdown` нужен, когда сервис останавливается или `connect` завершается ошибкой.

iOS вызывает `stage_session`, затем готовит сеть, затем `prepare_bridge` и качает пакеты через `push_packet` и `pop_packet_wait`. `shutdown` вызывается при остановке туннеля. `shutdown` включает `disconnect`.

Рабочий стол этот крейт не использует: он зовёт `Client` напрямую.

## Как устроено

`VpnCore::new` открывает `Client` с `HostPlatform` на переданном каталоге. Методы импорта, обновления, списков, групп, пинга и автоподключения проксируют сессию. Удаление группы не удаляет её серверы. Режим приложений и параметры туннеля читаются отдельными методами: MTU, включение всех сетей, исключение локальных сетей и APNs, скрытие значка.

## Сильные стороны

Мобильный контракт совпадает с методами сессии и не дублирует разбор ссылок. Ошибки не протекают типами Rust наружу: оболочка видит одну строку. Один объект привязан к одному каталогу данных.

## Слабые стороны

Оболочки iOS и Android в этом репозитории не собраны. Строка `VpnError` теряет исходный тип ошибки. Пока биндинги не сгенерированы, крейт проверяется только Rust-тестами фасада.
