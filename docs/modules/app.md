# rvpn-app

Сессия: подписки, Xray, маршрут, пинг и туннель. Границы — в [docs/architecture.md](../architecture.md).

## Ответственность

Крейт `crates/app` — единственное место, которое одновременно держит базу, процесс Xray и мост TUN. Окно и фасад UniFFI вызывают `Client` и не собирают JSON датаплана.

## Файлы

- `src/lib.rs` — `Client`, `Status`, `AppError`, `Reap`
- `src/session.rs` — подключение, отключение, снимок, насос пакетов
- `src/import.rs` — вставка текста, обновление подписки, ключ AES
- `src/ping.rs` — один узел и пачка
- `src/policy.rs` — настройки, выбор сервера, наложение меты
- `src/groups.rs` — группы серверов

## Основные типы

`Client` открывается на каталог данных и трейт `Platform`. `Status` — признак соединения, имя сервера, счётчики и сообщение. `Reap` — сессия жива, снята или замок занят. `ServerRow` — строка списка для окна. `AppError` собирает ошибки подписки, базы, маршрута, процесса, туннеля и платформы.

## Главный сценарий

Пользователь вставляет ссылку, обновляет список и вызывает `connect`. `connect` берёт внешний замок, вызывает `commit_routing`, пишет конфиг и ждёт локальный SOCKS. Прокси ОС, если он включён, указывает на `127.0.0.1`. `shutdown` включает `disconnect` и ещё раз восстанавливает снимок прокси.

## Как устроено

`session_lock` держат `connect`, `disconnect` и обновление, которое заменяет серверы. Замок базы берётся после него и только на короткий вызов. `ping` и `ping_many` этот замок не берут. `reap_dead_session` пробует замок через `try_lock` и сразу возвращает `Reap::Busy`, если он занят. Снятие сессии гасит TUN, возвращает прокси и останавливает статистику.

`set_stats_wanted` разрешает фоновый `statsquery`. Пока флаг выключен, поток спит. `stage_session` заполняет план для VpnService до появления TUN. Пачка пинга идёт потоками std, ширина — число ядер и не больше 16. Задержки пишутся одним проходом. `cancel_ping` обрывает хвост пачки.

Заголовки обновления: `user-agent`, `x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model`. `overlay_settings` копирует из меты только поля, которые мета задаёт: прокси, TUN, sniffing, HTTP, логин SOCKS и HTTP, список приложений, исключённые маршруты, no-limit, mux, пинг, URL проверки, fragment, noise и автозапуск. Настройки окна — непрозрачный blob, не `CoreSettings`.

Если мета просит подставить IP вместо имени, сессия резолвит адрес через DoH и сохраняет прежнее имя в SNI. Сервер с `Protocol::Json` уходит в `prepare_passthrough`.

## Сильные стороны

Черновик маршрута не попадает в процесс раньше `connect`. Пинг не стоит в очереди за подключением. Проверка мёртвой сессии не блокируется, если замок занят.

## Слабые стороны

Один `Client` рассчитан на один каталог данных. Статистика при включённом флаге всё ещё запускает отдельный процесс. Ошибка платформы доходит до окна уже строкой `Display`.
